# Internationalisation (i18n)

GrandMentor ships in **English (default)** and **Spanish**. Everything is built so a new language
can be added without touching application code.

## Adding a language

1. Add an entry to `web/js/languages.js` (`code`, `name`, `nativeName`, Intl `locale`, `dir`).
2. Copy `web/locales/en/` to `web/locales/<code>/` and translate the values (keep keys identical).
3. Optional content translations: `data/i18n/<code>/*.json` overlays (see below). Anything missing falls back to English.
4. Backend text (coach explanations, bot chat, review summaries): add the language to the `Lang` enum in `gm-content` and give each message table an entry (the compiler points to every `match` that needs one).

## Frontend

- `web/js/i18n.js`: `t(key, params)`, `getLanguage()`, `getLocale()`, `setLanguage()`, `onLanguageChange()`, `formatNumber()`, `formatDateIntl()`, `formatList()`.
- Messages: `web/locales/<lang>/<namespace>.js`, each `export default { ... }`, aggregated by `index.js`. Keys are `<namespace>.<key>`; nesting is allowed (`play.gameOver.title`).
- **Placeholders:** `"Good morning, {name}!"` → `t('home.greeting', { name })`. Never build sentences by concatenating translated fragments; word order differs between languages. Put the whole sentence, with placeholders, in one message.
- **Plurals:** `{ one: '{count} game', other: '{count} games' }` → `t('library.games', { count })`. An optional `zero` form is supported.
- **Lists:** messages can be arrays (tips, loading steps); `t()` returns the array.
- **Markdown-lite** (`**bold**`, `*italic*`) inside messages is fine wherever the code renders with `mdLite()`.
- **Never call `t()` at module top level.** Constants such as `const TIPS = [...]` must become functions or be resolved at render time; otherwise they freeze in the language active at import time.
- When the language changes, `app.js` re-renders the shell and **remounts the current page**, so pages only need to call `t()` while rendering.
- Every API request sends `Accept-Language: <lang>`.
- Dates and numbers use `formatDateIntl` / `formatNumber` (or `toLocale*String(getLocale())`), never a hard-coded `'en-US'`.
- Chess notation (SAN such as `Nf3`, `O-O`, `e8=Q`) and FEN/PGN are **not translated**.
- Proper names (bot names like "Pawnny", "Titan", the app name "GrandMentor") are not translated.

## Backend

- `gm-server` reads `?lang=` or else `Accept-Language` (first supported tag, default `en`) and passes a `Lang` (`En | Es`) down.
- Localized: bot descriptions, greetings and chat; coach move explanations and position ideas; the rule-based mentor chat (the Claude mentor is told to answer in the user's language); Game Review summaries and per-move explanations; user-facing error messages.
- Reviews are cached per game in the language they were generated in. Asking in another language regenerates the **text only** (explanations and summary) from the stored evaluations; the engine is not re-run.

## Content overlays (`data/i18n/<lang>/`)

The loader merges every file in the folder by prefix: `courses*.json`, `openings*.json`, `endgames*.json`, `classics*.json`. Splitting a language across several files, such as `courses.part1.json` and `courses.part2.json`, is fine. Missing ids or fields fall back to English. Moves, FENs, arrows and solutions are **never** in overlays; they always come from the English source.

```jsonc
// courses*.json
{ "<course_id>": {
    "title": "…", "description": "…",
    "lessons": { "<lesson_id>": {
        "title": "…", "summary": "…",
        "steps": [ { "text": "…", "task": { "prompt": "…", "hint": "…", "success": "…" } } ]   // same order/length as the English steps; use null for an untranslated step
        // interactive tasks also take "game": "…", "notes": ["…"] (guess) and "options": [{ "text": "…", "explain": "…" }] (choice), in English order
    } } } }

// openings*.json
{ "<opening_id>": { "name": "…", "family": "…", "description": "…", "ideas": ["…"], "traps": ["…"] } }

// endgames*.json
{ "<drill_id>": { "title": "…", "description": "…", "hint": "…", "technique": ["…"], "pitfall": "…",
    "lesson": ["…"] } }   // lesson: step texts, same order as the English lesson steps

// classics*.json (annotations/questions: same order/length as English, null = untranslated)
{ "<classic_id>": { "title": "…", "event": "…", "opening": "…", "summary": "…",
    "annotations": [ { "text": "…", "label": "…" } ], "questions": [ { "prompt": "…", "hint": "…", "explanation": "…" } ] } }
```

## Spanish style guide

- Address the player informally with **tú**: "Haz tu jugada", "¡Bien jugado!". The tone is warm and encouraging, like chess.com in Spanish.
- Use opening ¡ and ¿ and proper accents. Use sentence case for buttons and titles ("Nueva partida", not "Nueva Partida").
- Keep it short, because UI space is limited. Spanish runs about 20–30% longer than English, so prefer the shorter natural phrasing.

| tactic(s), puzzle(s) | táctica(s), problema(s) |

| zwischenzug, zugzwang | jugada intermedia, zugzwang |
